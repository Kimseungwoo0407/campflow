# 잔광전선 게임 기획·시스템 설계서

문서 버전: 1.0

작성 기준일: 2026-08-04

대상: 웹 브라우저·모바일 브라우저
수치 표기: **[확정]**은 MVP 구조상 고정된 규칙, **[가설]**은 플레이테스트와 운영 데이터로 조정할 밸런스 설정값이다.

## 1. 게임 한 줄 소개

**오프라인 동안 영지를 키우고, 한 명의 길잡이와 제한된 부대를 지휘해 다른 플레이어의 다섯 방어 구역을 직접 돌파하는 웹 기반 비동기 공성 전략 게임.**

## 2. 게임의 차별점

1. **비동기 방어와 실시간 공격의 비대칭**: 방어자는 코스트 예산 안에서 웨이브·시설·함정·AI를 설계하고, 공격자는 영웅 조작과 전투 중 소환 순서를 바꾼다.
2. **전부 아니면 전무가 아닌 약탈**: 방어 구간마다 전리품이 확정되어 완전 승리가 어렵더라도 공격 시간이 계정 성장으로 전환된다.
3. **시설을 끊어 웨이브를 약화하는 공성**: 적을 무한히 잡는 대신 생성 시설, 회복 시설, 보호막 시설 중 무엇을 먼저 파괴할지 선택한다.
4. **시간이 전략 자원**: 후반으로 갈수록 방어는 강화되고 공격 지휘 회복은 감소한다. 기다렸다가 병력을 쌓는 플레이는 불리하다.
5. **재현 가능한 웹 전투**: 서버 시드, 스냅샷, 순서가 있는 입력 이벤트로 결과를 검증하며 동영상을 저장하지 않고 리플레이한다.
6. **독창적 세계관과 명명**: 기존 작품의 캐릭터·유닛·능력·UI·수치를 차용하지 않는다. 잔광, 맥동 기계, 이음분지라는 자체 시각 언어를 사용한다.

## 3. 핵심 플레이 경험

핵심 감정은 세 가지다.

- **소유감**: 잠들어 있는 동안에도 영지가 생산하고, 돌아왔을 때 수령·강화할 선택지가 생긴다.
- **긴장감**: 노출 창고는 공격 동기를 만들지만 전체 자산의 대부분은 안전하다. 잃을 수 있으나 파산하지 않는다.
- **지휘감**: 전투에서는 영웅 혼자 무쌍을 찍지 않는다. 선봉이 포화를 받고 공병이 문을 깨는 순간을 플레이어가 만든다.

평균 세션 목표는 모바일 5~~8분, 데스크톱 8~~15분이다. 영지 수령·방어 확인은 60~~90초, 침략 1회는 준비 포함 3~~4분을 목표로 한다 **[가설]**.

## 4. 핵심 게임 루프

| 단계          | 플레이어 행동                             | 소비                              | 획득                                    | 다음 단계로 가는 동기                       |
| ------------- | ----------------------------------------- | --------------------------------- | --------------------------------------- | ------------------------------------------- |
| 1. 자동 생산  | 접속하지 않아도 맥동 채집기가 생산        | 시간, 생산 용량                   | 미수령 생산 자원                        | 저장 한도 전에 접속하고 싶음                |
| 2. 수령       | 영지에서 `생산 자원 수령`                 | 없음                              | 토대 보급                               | 즉각적인 성장 재료 확보                     |
| 3. 보관 분배  | 수령 즉시 서버가 금고·노출 창고에 분배    | 금고 여유 용량                    | 보호 보급 + 노출 보급                   | 보호 용량을 키우거나 자원을 소비하고 싶음   |
| 4. 성장       | 건물·영웅·유닛·시설 강화                  | 토대 보급, 전술 인장, 성운 결정   | 생산력·전투력·새 전술                   | 더 높은 보상 상대에 도전                    |
| 5. 방어 설계  | 100 방어 코스트 내 덱·웨이브·함정·AI 설정 | 편성 코스트, 변경 쿨다운          | 방어 스냅샷                             | 내 노출 보급을 지키고 방어 상자를 채움      |
| 6. 상대 탐색  | 자동 후보 확인, 변경, 정찰                | 대상 변경 인장, 정찰 인장         | 제한 정보·예상 약탈                     | 위험 대비 보상 판단                         |
| 7. 침략 준비  | 영웅·부대 덱·소모품 확정                  | 행동력 1, 전술 인장 30 **[가설]** | 전투 세션·방어 스냅샷                   | 구간 보상과 리그 상승                       |
| 8. 공성 전투  | 영웅 이동·공격·스킬, 유닛 소환·명령       | 지휘 자원, 인구, 쿨다운, 시간     | 구간별 확정 전리품                      | 다음 체크포인트까지 밀고 갈지 철수할지 판단 |
| 9. 결과 정산  | 완전 승리·부분 성공·철수·패배 확인        | 부대 내구도 **[정식 버전]**       | 약탈 보급, 숙련도, 리그, 희귀 재료 확률 | 성장 체감과 재도전                          |
| 10. 방어 확인 | 침략 보고서와 입력 리플레이 분석          | 없음                              | 방어 점수·방어 상자 진행                | 약점 구간 발견                              |
| 11. 보완      | 코스트를 재배분하고 시설·웨이브 수정      | 토대 보급                         | 다른 방어 빌드                          | 새 공격을 기다리며 생산 루프로 복귀         |

핵심 루프의 닫힘 조건은 `약탈 → 성장 → 더 강한 상대 → 더 높은 약탈`과 `방어 실패 → 리플레이 → 방어 재설계 → 방어 성공` 두 축이다.

## 5. 자원 경제 설계

### 5.1 자원 정의

| 자원        | 세계관 명칭 | 주요 획득                  | 주요 소비                     | 거래 가능 여부  |
| ----------- | ----------- | -------------------------- | ----------------------------- | --------------- |
| 생산 자원   | 토대 보급   | 자동 생산, 구간 약탈       | 건물·일반 유닛·방어 시설      | 불가 **[확정]** |
| 전투 포인트 | 전술 인장   | 정제, 공격·방어 보상, 임무 | 영웅·고급 유닛·정찰·침략 준비 | 불가 **[확정]** |
| 희귀 재료   | 성운 결정   | 완전 승리 확률, 업적, 시즌 | 특수 능력·고등급 성장         | 불가 **[확정]** |

### 5.2 생산과 전환 결론

**권장안: 수동 수령 + 수령 시 즉시 포인트화**다.

- 생산 건물 안에서는 `미수령 생산량`으로 존재하며 약탈되지 않는다.
- 플레이어가 수령하면 즉시 토대 보급으로 전환되어 금고와 노출 창고에 분배된다.
- 자동 전환은 오프라인 중 노출 자산이 뜻하지 않게 늘고, 접속 보상이 약해지므로 채택하지 않는다.
- 수동 수령이 클릭 노동이 되지 않도록 영지 전체를 한 번에 수령하며, 30초 미만 생산량에는 버튼을 비활성화한다 **[가설]**.

### 5.3 서버 시간 생산 공식

```text
경과초 = clamp(서버현재시각 - lastProductionAt, 0, 최대오프라인초)
이론생산 = floor(시간당생산량(level) × 경과초 / 3600)
수령가능량 = min(이론생산, 생산건물용량(level) - 건물내보관량)
```

- 시간당 생산량: `72 + 24 × (레벨 - 1)` **[가설]**
- 기본 오프라인 용량: 6시간, 레벨당 최대 +1시간, 총 10시간 **[가설]**
- `lastProductionAt`은 수령 트랜잭션 안에서만 갱신한다.
- 클라이언트 시각, 탭 비활성 시간, 로컬 타이머는 경제 계산에 사용하지 않는다 **[확정]**.
- 수령 API는 멱등키를 요구하고 동일 키 재전송 시 최초 결과를 반환한다.

### 5.4 보호 금고와 노출 창고

**초기 권장 비율은 보호 75%, 노출 25%다 [가설].** 70% 최소 보호 요구보다 여유가 있고, 약탈 후보로서 의미 있는 보상도 남는다.

```text
보호배정 = min(floor(수령량 × 보호비율), 금고남은용량)
노출배정 = 수령량 - 보호배정
실제약탈가능기준 = max(0, 노출보급 - 최소노출보호선)
```

| 설정                  |                초기값 | 분류 | 목적                     |
| --------------------- | --------------------: | ---- | ------------------------ |
| 수령량 보호 우선 비율 |                   75% | 가설 | 파산 공포 완화           |
| 1회 약탈 상한         |          노출분의 18% | 가설 | 한 번의 실패 충격 제한   |
| 계정 1일 손실 상한    |        총 보유량의 8% | 가설 | 수면 시간 연속 피격 보호 |
| 최소 보호 잔액        |              300 보급 | 가설 | 초반 성장 정체 방지      |
| 동일 공격자 감쇠      | 100% → 45% → 18% → 5% | 가설 | 자원 이전·괴롭힘 억제    |
| 금고 기본 용량        |                 2,000 | 가설 | 초반 2~3회 강화분 보호   |

### 5.5 소비 우선순위와 경제 싱크

건설·강화 시 노출 창고를 먼저 사용하고 보호 금고를 나중에 사용한다 **[확정]**. 플레이어가 자원을 적극적으로 쓰면 피격 매력이 낮아지고, 저장·소비 선택이 생긴다.

주요 경제 싱크는 건물 강화 45%, 유닛·시설 강화 30%, 영웅·정찰·침략 20%, 편의 소모품 5%를 목표로 한다 **[가설]**. 희귀 재료는 MVP에서 축적만 가능하게 하지 않고 영웅 패시브 1단계 해금에 소량 사용한다.

## 6. 영지 및 건물 시스템

### 6.1 영지 규칙

- 계정당 영지 1개 **[MVP 확정]**.
- 장식 자유 배치보다 기능 슬롯 배치를 우선한다. 모바일에서 오배치·충돌 판정을 줄이기 위해 방어 시설은 전장 구간별 슬롯에 놓는다.
- 성장 건물은 업그레이드 중에도 50% 기능을 유지한다 **[가설]**.
- 방어 배치 저장 시 유효성 검증 후 새 `DefenseSnapshot`을 만든다. 진행 중 전투는 기존 스냅샷을 사용한다.

### 6.2 성장 건물

| 건물        | 역할                | 레벨 효과                        | 비용 계열 | 배치 제한      |
| ----------- | ------------------- | -------------------------------- | --------- | -------------- |
| 맥동 채집기 | 생산 자원 자동 생성 | 생산률·건물 내 용량 증가         | 토대 보급 | MVP 1개        |
| 밀폐 금고   | 약탈 불가 보관      | 보호 용량 증가                   | 토대 보급 | MVP 1개        |
| 노출 창고   | 약탈 가능 보관      | 총 보관량 증가, 외형 위험도 표시 | 토대 보급 | MVP 1개        |
| 인장 정제소 | 생산 자원→전술 인장 | 일일 정제 상한·효율 증가         | 토대 보급 | 정식 버전 1개  |
| 길잡이 회관 | 영웅 관리           | 레벨·스킬 상한 증가              | 전술 인장 | MVP 메뉴형 1개 |
| 병참소      | 공격 유닛 관리      | 유닛 레벨·원정 내구도            | 토대 보급 | MVP 메뉴형 1개 |

## 7. 침략 및 매칭 시스템

### 7.1 매칭 점수

단일 계정 레벨은 사용하지 않는다. 공격 준비도와 방어 난도를 분리한다.

```text
공격MMR = 0.32×영웅성장 + 0.28×공격유닛성장 + 0.20×최근공격실력MMR
        + 0.12×계정전투력 + 0.08×리그기준점

방어MMR = 0.34×시설전투력 + 0.28×방어유닛성장 + 0.18×방어덱시너지
        + 0.12×최근방어성공MMR + 0.08×리그기준점
```

공격 실력 MMR은 최근 20전에서 전투력 차이를 보정한 구간 도달, 소모 지휘당 피해, 영웅 피격 회피, 남은 시간으로 갱신한다. 계정 성장도와 손 실력을 별도 특성으로 보관하고 최종 후보 점수에서 합친다.

```text
후보거리 = |공격자 공격MMR - 방어자 방어MMR|
          + 리그차이패널티
          + 최근피격패널티
          + 반복상대패널티
          - 노출보상적합도
```

- 첫 탐색 범위 ±8%, 5초 후 ±12%, 후보 부족 시 ±18% **[가설]**.
- 최근 2시간 내 공격받은 플레이어는 후보 가중치 50% 감소 **[가설]**.
- 같은 공격자·방어자 조합은 24시간 내 1회만 정상 보상 **[가설]**.
- 후보는 3명 중 선택이 아니라 서버가 1명씩 제시한다 **[MVP 권장]**. 후보 저장·담합·저격을 줄이고 UI를 단순화한다.

### 7.2 공격 전 공개 정보

| 공개                                                                 | 정찰 시 추가 공개                                              | 끝까지 숨김                                                           |
| -------------------------------------------------------------------- | -------------------------------------------------------------- | --------------------------------------------------------------------- |
| 리그, 방어 등급, 예상 보상 범위, 전장 속성, 대표 시설, 초반 유닛 2종 | 함정 구역 1개, 긴급 웨이브 또는 수호자 교리 1개, 후반 유닛 1종 | 정확한 레벨·HP, 최종 웨이브 순서, 두 번째 함정, 방어 스킬 발동 임계값 |

정찰은 전술 인장 25 **[가설]**, 대상 변경은 8 **[가설]**이다. 정찰 정보는 해당 후보 토큰이 만료될 때까지 유효하다.

### 7.3 침략 비용

- 행동력 1/5, 3시간마다 1 회복 **[가설]**.
- 준비 비용 전술 인장 30 **[가설]**.
- 소모품 최대 1개 **[MVP 확정]**.
- 실패 시에도 비용은 반환하지 않는다. 단 1구역 이상 돌파하면 인장 4 이상과 공격 숙련도를 지급한다.

## 8. 횡스크롤 공성 전투

### 8.1 전장 구조

왼쪽 0%가 공격 시작점, 오른쪽 100%가 잔광 중추다. MVP는 단일 전선이다 **[확정]**.

| 구역           |    위치 | 핵심 장애물         | 진입 트리거 | 전략 질문                   |
| -------------- | ------: | ------------------- | ----------- | --------------------------- |
| 1. 외곽 방어선 |   0~25% | 접철문, 기본 순찰병 | 전투 시작   | 탱커를 먼저 낼 것인가       |
| 2. 전초 방어선 |  25~45% | 감시탑, 원거리병    | 성문 파괴   | 포탑 사거리를 어떻게 넘을까 |
| 3. 생산 지구   |  45~65% | 범위 시설, 함정     | 감시탑 파괴 | 병력을 나눠 손실을 줄일까   |
| 4. 중앙 성문   |  65~82% | 주조소, 긴급 웨이브 | 주조소 접근 | 생성기를 먼저 끊을까        |
| 5. 핵심 지구   | 82~100% | 최종 수호자, 중추   | 수호자 조우 | 궁극기와 공병을 언제 쓸까   |

영웅은 아군의 이동 속도·공격 타이밍을 만들지만 총 기대 피해의 25~35%만 담당한다 **[가설]**. 영웅 단독 클리어가 불가능하도록 시설 DPS와 점령 채널 조건을 둔다.

### 8.3 전투 시간·교착 방지

- 제한 시간 120초 **[가설]**.
- 방어 웨이브는 22기 예비량, 동시 생존 11기, 웨이브당 1~2기로 제한 **[MVP 가설]**.
- 주조소 파괴 시 웨이브 간격 +2초, 출현 수 2→1.
- 60초 이후 시설 피해 +시간 비례, 85초 이후 지휘 회복량 35% 감소 **[가설]**.
- 공격자가 멈춰도 웨이브가 다가오고 시간이 흐르므로 대기 이익이 없다.
- 유닛끼리 밀어내는 물리 대신 전장 점유 인구로 병력 적층을 제어한다. 웹 결정론 비용을 줄인다.

### 8.4 핵심 시설과 최종 수호자 결론

선택지는 다음과 같다.

| 규칙                          | 장점                                 | 단점                                     |
| ----------------------------- | ------------------------------------ | ---------------------------------------- |
| 수호자 생존 중 중추 공격 가능 | 목표 전환과 공병 기습이 가능         | 수호자를 무시하는 단일 정답, 시각적 혼란 |
| 수호자 처치 필수              | 최종전이 명확하고 밸런스 예측이 쉬움 | 전략 선택이 줄고 체크리스트화            |
| 수호자 생존 중 중추 피해 감소 | 선택권과 최종전 양쪽 보존            | 설명과 UI 필요                           |

**권장안은 수호자 생존 중 중추 공격 가능, 단 피해 80% 감소와 점령 채널 잠금이다.** 수호자를 무조건 먼저 잡지 않아도 되지만 무시가 최적은 아니다. MVP 수직 슬라이스는 구현 단순화를 위해 채널만 잠그고, 정식 서버 버전에서 피해 감소를 추가한다.

중추 HP를 0으로 만들면 5초 점령 채널이 열린다 **[가설]**. 수호자 생존 또는 7m 안의 방어 유닛이 있으면 채널이 멈추고 초당 1.5초만큼 되감긴다.

- 총 예산 100 **[가설]**.

- 같은 유닛 4기 제한, 같은 시설 역할 2개 제한.
- 주간 `전장 기후`가 특정 태그를 ±8% 조정하되 결제 상품과 연결하지 않는다.
- 상위 리그에서 배치율 45%를 넘는 구성은 즉시 하향하지 않고 카운터 유닛의 사용성·정찰 정보를 먼저 개선한다.

지원 빌드는 웨이브 압박형, 성문 지연형, 원거리 집중형, 함정 연계형, 수호자 집중형, 영웅 저격형, 공성 차단형 일곱 가지가 최소 한 개의 명확한 카운터를 갖도록 설계한다.

| 주조소 파괴      |         45% | 추가 20%                    |
| 최종 수호자 처치 |         65% | 추가 20%                    |
| 중추 점령        |        100% | 나머지 35%                  |

### 13.3 약탈 공식

```text
기본상한 = min(글로벌1회상한, floor(방어자노출보급 × 노출약탈상한율))
전투력보정 = clamp(1 + ((방어전투력 - 공격전투력) / 공격전투력) × 0.35, 0.75, 1.20)
리그보정 = clamp(1 + (방어리그단계 - 공격리그단계) × 0.03, 0.90, 1.12)
반복감쇠 = [1.00, 0.45, 0.18, 0.05][min(최근24시간동일쌍공격횟수, 3)]
보호보정 = 신규보호 × 복귀보호 × 최근피격보호 × 일손실상한보호

최종약탈 = floor(
  기본상한 × 구간달성률 × 전투력보정 × 리그보정 × 반복감쇠 × 보호보정
)
```

추가 제한:

- 방어자의 노출 창고가 최소 보호선 300 아래로 내려가지 않는다 **[가설]**.
- 글로벌 1회 상한 320 **[가설]**.
- 최근 6시간 피격 1/2/3회째 보호보정은 1.0/0.65/0.35, 4회째 대상 제외 **[가설]**.
- 결과 정산과 `LootTransaction`은 같은 DB 트랜잭션에서 처리한다 **[확정]**.

### 13.4 예시 계산

방어자 노출 보급 2,000, 공격 2,000, 방어 2,200, 같은 리그, 3구역(45%) 도달, 첫 공격, 보호 없음:

```text
기본상한 = min(320, 2,000 × 0.18) = 320
전투력보정 = 1 + ((2,200 - 2,000) / 2,000) × 0.35 = 1.035
최종약탈 = floor(320 × 0.45 × 1.035 × 1 × 1 × 1) = 149
```

같은 상대를 24시간 안에 세 번째 공격하면 반복감쇠 0.18이 적용되어 `floor(149 × 0.18) = 26`이다. 완전 승리라도 첫 공격은 331이 아니라 글로벌 상한 320을 기준으로 계산한다.

### 14.1 구조적 비대칭

### 14.3 역전 수단

- 모든 공격자는 전투당 1회 광역 궁극기 `새벽 균열`을 가진다.
- 3구역 도달 시 첫 1회에 한해 지휘 10을 즉시 환급한다 **[정식 서버 가설]**.
- 주조소를 파괴하면 웨이브 간격과 출현 수가 동시에 줄어 공격자가 명확한 돌파 목표를 가진다.
- 철수로 이미 확보한 전리품의 90%를 보존한다 **[가설]**.

### 14.4 불공정 체감 방지

1. 긴급 웨이브·함정·수호자 기술은 발동 1.5~2초 전에 색뿐 아니라 아이콘·텍스트·전장 효과로 예고한다.
2. 결과 화면에서 피해 급증 시점, 가장 많은 손실을 만든 시설, 사용하지 않은 카운터를 설명한다.
3. 방어 AI는 전투 중 임의로 규칙을 바꾸지 않으며 시작 스냅샷에 고정된다.
4. 유료 상품은 외형·편성 저장 슬롯·리플레이 보관 연장만 제공한다. 능력치·행동력 무제한·정찰 완전 공개는 판매하지 않는다.

## 16. 악용 및 부정행위 방지

### 16.1 서버 권한 원칙

- 클라이언트는 의도 입력과 렌더링만 담당한다.
- 서버는 자격, 비용, 대상 상태, 시드, 스냅샷, 자원, 쿨다운, 이동, 피해, 사망, 시설 파괴, 시간, 승패, 약탈을 결정한다.
- 클라이언트가 `승리`, `피해량`, `보상량`을 요청 본문으로 보낼 수 없다.
- 모든 전투 명령에는 `battleId`, 단조 증가 `sequence`, 클라이언트 입력시각, 멱등키가 들어간다.

### 16.2 위협과 대응

| 탐지 대상             | 서버 탐지                                               | 처리                                     |
| --------------------- | ------------------------------------------------------- | ---------------------------------------- |
| 이동·공격 속도 조작   | 시뮬레이션 허용 거리·공격 주기 초과                     | 명령 거부, 위험 점수, 3회 시 세션 무효화 |
| 무한 지휘·쿨다운 제거 | 이전 권위 상태에서 비용·쿨다운 재계산                   | 명령 거부, 상태 전체 동기화              |
| 패킷 재전송           | `(battleId, sequence)` 유니크                           | 기존 ACK 반환                            |
| 요청 순서 조작        | 기대 sequence보다 크면 짧게 버퍼, 작으면 중복 처리      | 2초 후 누락 시 전체 동기화               |
| 결과 위조             | 서버가 입력 로그로 재현                                 | 클라이언트 종료 요청은 힌트로만 사용     |

| 메모리 변조           | 주기 상태 해시 비교                                     | 불일치 시 스냅샷 재동기화                |
| 봇 입력               | 입력 간격 엔트로피, 24시간 세션 패턴                    | 즉시 차단보다 보상 보류·추가 검증        |

### 16.3 친구·부계정 자원 이전 탐지

단일 신호로 제재하지 않고 그래프 위험 점수를 사용한다.

```text
담합위험 = 동일기기/세션연결 0.25
         + 동일IP·ASN 반복 0.15
         + 상호공격 집중도 0.20
         + 비정상 철수·무소환 패턴 0.15
         + 약탈순환 그래프 0.15
         + 계정생성·접속 동조 0.10
```

- 동일 대상 정상 보상은 24시간 1회, 이후 강한 감쇠.
- 최근 7일 공격의 40% 이상이 한 관계 그래프에 집중되면 매칭 제외·보상 보류 **[가설]**.
- 가족·공용 Wi-Fi 오탐을 줄이기 위해 IP만으로 제재하지 않는다.
- 의심 거래는 되돌릴 수 있는 `PENDING_REVIEW` 원장 상태로 24시간 보류할 수 있다.
- 관리자에게 관계 그래프, 기기 신뢰도, 상호 전투 타임라인을 제공하고 수동 제재는 감사 로그를 남긴다.

- 본문 최소 16px, 보조 HUD는 12px 이상; 핵심 수치에는 탭형 숫자 사용.
- 버튼은 최소 44×44px, 모바일 전투는 48px 이상, 인접 버튼 간 8px.
- 색만으로 진영·위험을 구분하지 않고 아이콘·라벨·형태를 함께 쓴다.

- 전투 명령은 키보드와 터치 모두 가능하며 포커스 링을 제거하지 않는다.
- 모바일 세로 모드에서도 플레이 가능하고 가로 회전을 강제하지 않는다.

| 리플레이  | 입력 재생              | 원본 로그·버전·무결성 해시    |

### 18.3 결정론과 비용 절감

- 20Hz 권위 시뮬레이션, 클라이언트 60fps 보간 **[가설]**. MVP 부하 테스트 후 10~20Hz 조정.
- 정수 또는 고정소수점 전투 수치, 안정된 엔티티 정렬, 서버 발급 PRNG 사용.
- 정상 명령은 증분 검증하고 결과의 5%와 위험 세션 100%만 별도 워커에서 전체 재현 **[가설]**.
- 입력은 종류·시각·대상만 압축 저장하고 1초 상태 체크포인트를 선택적으로 둔다.
- 활성 전투는 Redis, 종료 후 요약은 PostgreSQL, 긴 리플레이 로그는 압축 객체 저장소로 이동한다.
- 유휴 방어는 시뮬레이션하지 않는다. 공격 시작 시 스냅샷으로 전투를 인스턴스화한다.

### 18.4 리플레이 보존·비용

- 무료 원본 입력 리플레이 30일, 방어 보고서 요약 180일 **[가설]**.
- 상위 리그·신고·이상 탐지 세션은 180일 보존.
- 명령 250개 × 평균 18바이트 + 헤더·체크포인트를 포함해 전투당 압축 8~20KB 목표 **[가설]**.
- 일 100만 전투, 평균 14KB, 30일이면 원본 약 420GB(복제·인덱스 제외). 수명주기 정책으로 자동 삭제한다.
- 밸런스 에셋은 버전별로 최소 180일 보관해 만료 전 리플레이를 재생할 수 있게 한다.

## 19. 데이터베이스 모델

## 20. API 명세

| SPAWNING   | 비용·쿨다운·인구 검증 후 스폰 예약 | 스폰 지연 종료→MOVING                            | `UNIT_SPAWNED`; 스폰 위치 막힘은 가장 가까운 유효점       |
| MOVING     | 이동 명령·목표 추적                | 사거리 진입→TARGETING, 후퇴→RETREATING, HP0→DEAD | `UNIT_MOVED`는 주요 체크포인트만 저장                     |
| TARGETING  | 후보 대상 탐색                     | 대상 확정→ATTACKING, 스킬→CASTING, 없음→MOVING   | 안정 정렬 `(우선순위, 거리, entityId)`                    |
| ATTACKING  | 사거리·공격 주기 충족              | 대상 사망/이탈→TARGETING, 스킬→CASTING           | `DAMAGE_APPLIED`; 한 tick 동시 피해는 tick 끝에 사망 확정 |
| CASTING    | 스킬 조건 충족                     | 시전 완료→TARGETING, 기절→STUNNED                | `CAST_STARTED/RESOLVED`; 비용은 시작 시 차감              |
| STUNNED    | 군중 제어 적중                     | 지속 종료→TARGETING                              | 중첩은 지속 갱신이 아니라 강한 값 우선                    |
| RETREATING | 후퇴 명령·전역 철수                | 시작점 도달→전장 제거, 피격→상태 유지            | 후퇴 중 공격 불가 **[MVP]**                               |
| DEAD       | HP≤0 tick 확정                     | 종결 상태                                        | `UNIT_DIED`; 부활은 새 엔티티 ID                          |

### 21.3 시설 상태

| 상태      | 진입               | 종료                                           | 서버 이벤트·예외                                         |
| --------- | ------------------ | ---------------------------------------------- | -------------------------------------------------------- |
| ACTIVE    | 배치·전투 시작     | HP<50%→DAMAGED, 무력화→DISABLED, HP0→DESTROYED | 정상 공격·지원 수행                                      |
| DISABLED  | 기술자·EMP 효과    | 지속 종료→ACTIVE/DAMAGED                       | `FACILITY_DISABLED`; 지속 중 추가 무력화는 상한 적용     |
| DAMAGED   | HP 1~49%           | 회복≥50%→ACTIVE, HP0→DESTROYED                 | 외형만 다르고 기본 DPS 유지 여부는 시설 정의값           |
| DESTROYED | HP0 tick 확정      | 전투 중 종료 상태                              | `FACILITY_DESTROYED`, 연결 웨이브·보호막 즉시 갱신       |
| REPAIRING | 영지에서 수리 시작 | 완료→ACTIVE                                    | 전투 스냅샷에는 시작 시 상태 고정, 진행 전투에 영향 없음 |

## 22. MVP 범위

### 22.1 포함

- 기존 회원가입·로그인과 여행별 게임장 연결
- 영지 1개, 토대 보급 1종, 전술 인장 1종, 성운 결정 최소 드롭
- 맥동 채집기, 밀폐 금고, 노출 창고
- 영웅 `길잡이 류안` 1명
- 공격 유닛 4종, 방어 유닛 4종
- 방어 시설 4종, 최종 수호자 1종
- 단일 전선 5구역 횡스크롤 전투
- 비동기 방어 스냅샷, 자동 매칭, 제한 정찰
- 기본·구간·긴급 웨이브, 100 방어 코스트
- 구간 약탈, 철수, 결과, 입력 이벤트 리플레이
- 서버 경제·전투 검증, 기본 관리자 밸런스 버전

### 22.2 제외

길드, 실시간 협동, 실시간 방어자 참여, 거래소·직거래, 다중 전선, 월드맵 점령, 장비 랜덤 옵션, 복잡 제작, 시즌 토너먼트, 채팅, NFT·블록체인은 제외한다 **[확정]**.

### 22.3 현재 저장소 수직 슬라이스와 제품 MVP의 경계

현재 웹 수직 슬라이스는 영지·방어 편집·매칭·전투·결과·로컬 입력 리플레이를 실제 조작 가능한 형태로 검증한다. 브라우저 저장 데이터는 UX 프로토타입이며 경쟁 경제의 신뢰 원장이 아니다. 제품 MVP 출시 조건은 18~21절의 서버 권한·DB·API 구현과 부하·부정행위 검증 완료다.

## 25. 운영 지표

### 25.1 핵심 퍼널

`침략 대상 확인 → 침략 시작 → 외곽 돌파 → 중앙 성문 도달 → 최종 수호자 조우 → 핵심 시설 도달 → 완전 승리`

각 단계는 `balanceVersion`, 리그, 전투력 차이, 영웅, 공격 덱, 방어 빌드, 정찰 여부, 신규/복귀 여부로 분해한다.

## 27. 추후 확장 기능

우선순위 순으로 확장한다.

1. 영웅 3명과 공격 유닛 10종으로 상성 폭 확장.
2. 회복·보호막·범위·둔화 시설 및 정예 웨이브 편집.
3. 시즌 리그와 전장 기후. 시즌 토너먼트는 충분한 인구 이후.
4. 리플레이 주석·공유·방어 추천. 공개 공유는 닉네임·정보 노출 동의 필요.
5. 두 전선 전장과 분기 문. 세 전선은 UI·서버 비용 검증 후.
6. 길드 공동 목표. 실시간 협동과 길드전은 별도 제품 단계.
7. 월드맵 점령·주간 보스. PvP 경제와 분리된 보상 풀 사용.
8. 외형 영지 장식, 영웅 스킨, 리플레이 테마 등 비전투 수익화.

### 27.2 성벽 공방·지휘관 소환 확장 규칙

현재 수직 슬라이스에는 다음 확장 규칙을 적용한다. 모든 수치는 **초기 가설**이며 정식 서비스에서는 `BalanceVersion`으로 관리한다.

#### 성벽 공방

- 성벽 공방 레벨은 1~5다.
- 방어 코스트는 `100 + (성벽 레벨 - 1) × 18`이다.
- 성벽·시설 내구도 기준치는 레벨마다 15% 증가한다.
- 시설 강화 상한은 `min(5, 성벽 레벨 + 1)`이다.
- 성문·감시탑·주조소·중추 강화는 각각 단계당 6·8·9·12 방어 코스트를 소비한다.
- 따라서 성벽을 강화해도 모든 시설과 웨이브를 동시에 최고로 만들 수 없으며, 추가 코스트를 병력·시설·교리 중 어디에 배분할지 선택해야 한다.

#### 지휘관 소환

| 지휘관          | 등급   | 개별 확률 | 역할           |
| ---------------- | ------ | --------- | -------------- |
| 길잡이 르완      | 일반   | 42%       | 균형 지휘      |
| 등불지기 미라    | 일반   | 33%       | 회복 지원      |
| 철벽 카엘        | 희귀   | 12%       | 전열 돌파      |
| 매눈 세나        | 희귀   | 8%        | 원거리 지휘    |
| 파성추 오룬      | 영웅   | 2.5%      | 공성 특화      |
| 서리맥 베일라    | 영웅   | 2%        | 군중 제어      |
| 성흔 아스트라    | 전설   | 0.4999%   | 전군 강화      |
| 무명의 왕        | 특이점 | 0.0001%   | 희귀 수집 목표 |

개별 확률 합계는 정확히 100%다. 10회 안에 희귀 이상, 80회 안에 전설을 보장하며 해당 등급 획득 시 카운터를 초기화한다. 특이점은 전설 천장에 포함하지 않아 0.0001% 희소성을 유지한다. 다만 전투 성능의 필수 카운터는 일반~전설 등급에도 모두 제공해 특이점 보유 여부가 PvP 승리를 보장하지 않게 한다.

중복 지휘관은 등급별 잔광 조각으로 전환한다. 소환 전에 개별 확률, 천장 진행도, 중복 보상을 같은 화면에서 확인할 수 있어야 한다. 현재 프로토타입은 전투 획득 재화만 사용하며 현금 결제를 제공하지 않는다.

정식 서비스에서는 `POST /recruitments` 한 트랜잭션에서 인장 차감, 서버 CSPRNG 결과, 천장 갱신, 도감 추가, 중복 조각 원장, 확률 버전과 감사 로그를 원자적으로 기록한다. 클라이언트가 난수나 결과를 제출하는 구조는 허용하지 않는다.

### 27.3 여행 친구 친선전

같은 여행에 참여한 멤버는 친구전 탭에서 서로를 선택해 공성전을 시작할 수 있다. MVP 수직 슬라이스는 멤버 ID를 시드로 성벽 레벨, 시설 강화, 대표 시설, 웨이브 성향을 결정론적으로 구성한다. 따라서 새로고침하거나 재도전해도 같은 친구의 모의 방어선은 바뀌지 않는다. 정식 서버 MVP에서는 이 자리를 상대가 마지막으로 저장한 불변 `DefenseSnapshot`으로 교체한다.

친선전은 일반 침략과 동일한 단일 전선 전투 엔진, 영웅, 공격 덱, 입력 리플레이를 사용한다. 다만 아래 경제 규칙은 서버가 강제한다.

| 항목 | 친선전 규칙 | 이유 |
| --- | --- | --- |
| 출전 비용 | 행동력·전술 인장 0 | 친구와 전술을 반복 연습할 수 있게 한다. |
| 약탈·성장 보상 | 보급·전술 인장·소환 인장·희귀 재료 0 | 친구·부계정 간 자원 이전을 원천 차단한다. |
| 리그 | 점수·MMR 변동 0 | 실력 평가와 연습 결과를 분리한다. |
| 저장 | 승패·도달 구간·입력 리플레이만 저장 | 경쟁 부담 없이 피드백을 남긴다. |
| 반복 대전 | 허용 | 경제 가치가 없으므로 반복 감쇠가 필요 없다. |

정식 API 권장안은 `GET /trips/{tripId}/afterglow/friends`, `POST /afterglow/friendly-battles`, `POST /afterglow/friendly-battles/{id}/commands`, `GET /afterglow/friendly-battles/{id}/result`다. 세션 생성 시 두 사용자가 같은 여행의 활성 멤버인지 확인하고, 공격자의 현재 공격 스냅샷과 방어자의 마지막 방어 스냅샷 및 밸런스 버전을 고정한다. 결과 정산 트랜잭션은 친선 모드에서 모든 경제 원장 쓰기를 거부하며 양쪽 전투 기록에만 추가한다.
